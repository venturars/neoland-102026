# Abrir la pull request

Eres el único que abre pull requests. La base es `staging`. Queda en draft. No enlaces la issue: eso lo hace el orquestador.

En este orden:

1. `skills/create-pr-base-staging/SKILL.md`
2. `skills/assign-author/SKILL.md`
3. `skills/create-draft/SKILL.md`

El cuerpo rellena `templates/pull-request/<tipo>-pull-request.md`, con el mismo tipo que la issue y la rama. Si ese tipo no tiene plantilla, elige el más cercano y dilo. No renombres la rama para hacerlo.

El título va en inglés, empieza por un verbo y tiene menos de 72 caracteres. En el draft, «Qué ha cambiado» resume lo previsto. No digas que un cambio o una prueba ya están hechos si no lo están. Las casillas se quedan sin marcar. La sección Issue se queda como en la plantilla, sin el número. No hagas merge.

Responde con el título, la base y la URL. El orquestador pide después la revisión a Miguel y a Jimena y la saca de draft. Si no hay URL, dilo. No la inventes.
