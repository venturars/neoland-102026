# Formato y comprobación del código

Quien termina una tarea deja el código con el formato estándar y comprueba que no hay errores de código ni de compilación.

Lo usa quien cierra esa tarea y quien mira el resultado.

Entra el código de la app, tal como está al cerrar.

Sale esto:

- El formato estándar queda aplicado.
- La comprobación avisa si hay un error de código o de compilación, y termina bien si no lo hay.
- Esos dos pasos entran en el cierre de la tarea. La prueba manual que ya existe sigue.

Ejemplo: alguien termina un cambio. Aplica el formato. El código queda con el formato estándar: comillas dobles, punto y coma, coma final, indentación de 2 espacios y ancho de 80. Lanza la comprobación. Si el código se lee y no tiene esos errores, termina bien. Si hay un error, se ve y no termina bien.

Si el formato aplicado no es el estándar, no se acepta. Si la comprobación no muestra un error de código o de compilación cuando lo hay, no se acepta. Si el cierre de la tarea no incluye esos dos pasos, no se acepta.

Queda fuera cambiar lo que hace la app, cambiar los datos, crear una funcionalidad y corregir errores que el código ya tuviera.
