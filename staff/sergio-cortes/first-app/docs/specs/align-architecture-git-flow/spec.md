# Alinear la arquitectura con el flujo de git del ejercicio

El flujo de git de esta app sigue el ejercicio del flujo de git. La
documentación de arquitectura describe ese flujo con datos anteriores.
Dice que hay seis plantillas de issue y seis de pull request, y el
ejercicio ya tiene siete, con el tipo de conocimiento. Dice también que
el mensaje del commit nombra el fichero, y la regla actual dice lo
contrario en la primera línea: no lleva rutas de fichero.

Lo lee quien construye la app con IA para saber cómo es el flujo. Lo
revisa quien comprueba que la documentación coincide con el ejercicio.

Entra la corrección de esas tres frases en el bloque del flujo de git
de la arquitectura. Sale el mismo bloque con las cifras y la regla del
ejercicio.

Ejemplo: el bloque dice que `templates/issues/` lleva siete plantillas,
incluida la de `knowledge`. Y dice que la primera línea del commit no
lleva rutas de fichero; el cuerpo es el que nombra las funciones o
ficheros implicados.

No hay un fallo de la lista «Errores». Si el bloque sigue diciendo seis
o que el mensaje nombra el fichero en la primera línea, la documentación
no coincide con el ejercicio.

Queda fuera el resto de la arquitectura, el flujo en sí, las skills, las
plantillas, los agentes, la constitución, el manual de la carpeta, el
código y las specs ya escritas.
