# Guiar de la issue a Empezar

Issue: #922.

Quien usa el orquestador de git del curso deja una issue escrita y, si
a continuación hay cambios, ve que el momento siguiente es Empezar:
rama desde staging, commit vacío, push y pull request en draft
enlazada a la issue.

Cambios es cualquier toque al proyecto: código, documentación, specs,
ficheros o carpetas. Da igual el flujo del proyecto.

Lo usa quien construye un proyecto con ese orquestador.

Entra una issue ya escrita y un trabajo que va a hacer cambios. Sale
Empezar. Si solo se deja la issue y se para, no se abre rama ni pull
request. La guía dice el momento que sigue, no un candado.

Ejemplo: se pide un cambio, la issue queda escrita y el siguiente
paso es una spec, un documento o código. El orquestador sigue con
Empezar. Ese trabajo se hace con la pull request ya abierta.

No hay un fallo de la lista «Errores». Si con la issue escrita y
cambios a continuación el orquestador para y no pasa a Empezar, la
guía no está.

Queda fuera la guía de trabajo de first-app, reabrir el contrato de
integración ya retirado, scripts, subagentes y el resto de momentos.
