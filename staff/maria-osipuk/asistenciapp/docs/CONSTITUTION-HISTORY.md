# Historial de enmiendas

Este documento conserva las decisiones y sus motivos. Los principios vigentes están en [CONSTITUTION.md](CONSTITUTION.md). Las referencias a secciones corresponden a la versión de cada enmienda.

| Versión | Fecha      | Cambio                                                                                                                                                                                                                                       | Motivo                                                                                                                                                                       |
| ------- | ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1.0     | 2026-10-19 | Versión inicial                                                                                                                                                                                                                              | Arranque del proyecto                                                                                                                                                        |
| 1.1     | 2026-10-19 | §6: los códigos no deben poder adivinarse _a mano_; la protección contra scripts deja de ser obligatoria                                                                                                                                     | En una clase el riesgo real es un alumno ausente, no un ataque automatizado. Evita añadir límites de intentos que no aportan al MVP (P2)                                     |
| 2.0     | 2026-10-20 | §3: stack Node.js → Python (Flask + pytest). P3 pasa de "cero dependencias" a "dependencias mínimas" y permite Flask y pytest                                                                                                                | Requisito nuevo: el proyecto debe hacerse en Python. Se elige Flask por ser simple y muy extendido, y pytest por su sintaxis sencilla                                        |
| 2.1     | 2026-10-20 | P4: distingue _almacenar_ (solo en local) de _transitar_ (puede pasar cifrado por un proveedor de túnel)                                                                                                                                     | Los alumnos asisten desde casa y necesitan llegar a la app del profesor; un túnel es la forma más simple (spec 001, HU-08)                                                   |
| 2.2     | 2026-10-23 | §4: ningún fichero de esta app sin spec local aprobado; issue, rama y pull request no sustituyen al spec; las specs de otras aplicaciones no autorizan. §7: raíz local de la aplicación. §8: aprueba la persona responsable de la aplicación | El texto solo frenaba el código; README y tests podían cambiarse sin spec. Las reglas nombraban otra carpeta (spec 002, issue #287)                                          |
| 3.0     | 2026-10-26 | P4: excepción para guardar la dirección de red solo al contar intentos de registro y en la lista de bloqueo                                                                                                                                  | La issue #400 pide ese tope y una lista que sobreviva al reinicio. La enmienda 1.1 no lo prohibía; este tope es un requisito nuevo, no una protección general contra scripts |
| 3.1 | 2026-11-02 | Reorganización editorial: principios en la constitución, proceso en AGENTS, estilo e historial en sus guías. P5, §6 y §7 conservan sus criterios concretos | Aclarar las responsabilidades de cada documento sin eliminar ni contradecir ningún principio, por eso es versión menor. Conserva las aprobaciones SDD (spec 009, issue #754) |
| 3.2 | 2026-11-03 | §4: la intervención humana pasa a cinco momentos (issue, draft, specs, implementar, pull request). Spec, plan y tareas se escriben en la misma pasada, sin ok entre ellas. Una issue, una rama o una PR siguen sin autorizar el código | Alinear el flujo con el del curso. Las fases y su orden se conservan; solo cambia dónde se para, por eso es versión menor |
