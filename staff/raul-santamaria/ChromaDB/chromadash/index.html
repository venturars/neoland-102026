FAQ's



Adding documents via the fastAPI doesnt auto generate the embeddings - i thought its supposed to?

When adding documents via the FastAPI, embeddings are not automatically generated. The FastAPI routes for adding embeddings (/api/v2/tenants/default_tenant/databases/default_database/collections/{collection_id}/add) expect the embeddings to be provided explicitly in the request body.
Therefore, you need to provide the embeddings explicitly when adding documents via the FastAPI. If you want to auto-generate embeddings from documents, you would need to implement that logic separately, possibly by using an embedding function before making the API call.




Do only the python and node.js libraries contain the embedding functions you need to use before sending the "add document" API call to the rest API? Is that what the documentation means by "it embeds documents for you automatically?" But only if done using a chroma library?

Yes, the Python and JavaScript (Node.js) client libraries for Chroma contain the embedding functions needed to embed documents before sending the "add document" API call to the REST API. This is indicated by the classes such as OpenAIEmbeddingFunction, CohereEmbeddingFunction, and DefaultEmbeddingFunction in the JavaScript client, and similar functionality in the Python client.
The documentation implies that these client libraries handle the embedding of documents automatically when you use them, which means that if you use the Chroma client libraries, the documents will be embedded for you before being sent to the REST API. This automatic embedding does not occur if you make a direct REST API call without using the Chroma client libraries. Refer to the JavaScript Client and Python Client sections for more details
